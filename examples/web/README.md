# Web example

使用真实模型时，在仓库根目录运行：

```bash
uv sync --locked --extra web
npm --prefix web-ui ci
node scripts/build-web.mjs
uv run build-skills web
```

源码构建需要 Node.js 22 和 Go，Go 版本见 `tools/workflow-compiler/go.mod`。发布 wheel 内含构建后的前端、Starlark 源与编译描述，使用 wheel 不需要 Node/Go。维护者修改流程后运行 `node scripts/compile-workflow.mjs`；用户只填写节点表单。

默认端口为 8321，被占用时依次尝试 8322、8323、8324。四个端口都被占用时显示“Web 启动失败：端口被占用”，退出码为 2，不再继续偏移。打开启动日志中显示的实际地址。若显式使用其他端口，例如 `--port 9000`，仅尝试该端口，占用即失败。

默认统一模型为 `codex-sol-5.6-high`，调用 Codex 的 `gpt-5.6-sol`、思考等级 `high`，负责构建、评估、重构，以及材料解析和准备。默认执行模型为 `qoder-qwen3.8-flash`，调用 `qodercli` 的 `Qwen3.8-Flash`。模型名称是配置值，实际可用性由本机 CLI 与账号决定。

只演示流程、不调用真实 LLM 时，显式选择合成示例配置：

```bash
uv run build-skills web --config examples/web/config.toml
```

两种启动方式共用 Web 流程，但各自保存本地默认配置，演示设置不会覆盖真实模型默认值。

1. 在“导入材料”节点选择文件、文件夹、Git 或文件链接。先查看文件树并勾选材料，再点击“导入所选文件”。可使用本目录 `materials/copy-text.md` 或下方 URL 示例。目录保留相对路径，不同目录的同名文件可区分。未选择的文件不会进入解析。
2. 在“模型与流程”节点填写目标，选择一个统一负责构建、评估、重构的模型，再添加一个或多个执行模型。下拉选择预设；展开“修改模型或思考等级”可自定义。执行模型允许重复，每项还可通过“每项模型的场景重复次数”重复执行。设置 Loop 最大轮次和最低分数。
3. 点击“解析并核对材料”。复杂文件交给统一构建模型；纯文本任务不增加解析模型调用。页面展示每个文件的文字和警告，核对后勾选确认，再点击“采用材料并生成草案”。
4. 页面按范围、评估标准、来源、开发场景和保留场景展示草案。有问题时逐条填写答案，点击“提交回答并更新草案”，由模型将答案落实到草案中。也可填写其他修改意见。审阅更新后的草案；所有问题解决后，勾选已审阅，点击“确认并开始构建”。无需编辑 JSON。
5. Pipeline 沿纵向主线显示步骤，重构显示为开发评估旁的支路。点击侧栏会展开并滚动到对应节点，同时暂停自动跟随；状态刷新保留手动选中的步骤。点击“跟随当前节点”恢复自动定位。等待开发测评与独立保留验证完成，在“交付与导出”复制本地地址或下载 Skill ZIP、测评 JSON。刷新或切换“本地任务”恢复同一运行；模型参数和已导入批次的未提交草稿保存在当前标签页。浏览器不能恢复尚未导入的 File 对象，刷新后需重新选择那些文件。

显式指定 `examples/web/config.toml` 的演示使用两个确定性进程替身，固定执行文本复制场景，不调用真实 LLM。复杂文件的演示解析也只返回固定合成文本，并附带“不是实际文档解读”的警告；它验证本地路径交接、结果校验与人工核对流程，不验证真实文件识别质量。实际解析请使用自己的 Agent 配置。

- 文件链接：`https://raw.githubusercontent.com/wind8ai/build-skills/codex/web-ui/examples/web/materials/delivery-smoke.md`；读取后仍需勾选文件。
- 文件夹：选择本地 `examples/web/materials/`，只勾选 `copy-text.md`，进入相同核对和构建流程。

当前支持公开 HTTP(S) 的标准端口；拒绝 URL 用户名/密码、内网地址和普通网页入口。私有仓库认证尚未接入。Git 拉取最多 45 秒、50 MB，文件树最多 5000 项，不执行 checkout、过滤器、钩子、仓库脚本或子模块；符号链接、子模块和 LFS 指针不能作为材料。直接文件下载最多 30 秒、10 MB，逐次验证重定向（最多 5 次）。目录和仓库默认排除 `.git`、`.venv`、`node_modules`、`.build-skills`、`.env` 等本地环境文件。其他敏感文件仍由用户在文件树中判断是否应选取。

## 真实模型

将已有的 Codex/Qoder 配置放入 `.build-skills/` 下，用 `--config` 指向它。配置须满足现有 CLI 的校验规则，包括可读取的初始 materials。Web 新任务会以本次上传材料替换 materials，并创建独立 workspace。可参考 [CLI 配置说明](../../docs/cli.md)。

网页按两组职责配置模型：构建、评估、重构统一使用一个选择；执行是一个可重复的列表。解析和准备也使用统一模型。执行列表每一项会生成独立的 `executor_1`、`executor_2` 等 provider 引用，即使模型相同也分别记录执行结果和调用预算。比如同一执行模型添加两次，场景重复次数设为 2，则每个场景共执行 4 次。

点击“保存为默认配置”会保存当前模型选择、执行列表、Loop 上限、重复次数、最低分数、每次模型调用超时与解析超时。保存位置显示在网页中，为 `.build-skills/web/defaults/<配置标识>.json`；刷新、重启和新任务会读取它。也可直接编辑此文件，下次读取时校验。不会改写仓库中的预设、启动配置或已有任务快照。

模型候选来自随包预设或 `--config` 指定的 provider；保存的自定义选择也会成为候选。自定义模型仍通过已有可信 Agent 连接调用，网页不能添加任意命令。命令、权限、阶段调用次数/总时间预算和提示模板沿用本地配置。网页中的“每次模型调用超时”默认 600 秒，统一应用于新任务的准备、构建、重构、执行和评估；已有任务快照保持不变。材料解析单独配置超时，默认 600 秒，每个任务最多一个批次调用，不消耗 prepare 或 Loop 的调用次数预算。
启动前完成相应 CLI 登录。Agent 读取原件时可能将文件文字或图像发送给模型服务；后续运行还会按照 provider 配置发送任务内容及运行证据；“本地”指 Web、文件存储和进程运行位置，不表示模型推理离线。

## 文件支持

| 类型 | 处理方式与限制 |
| --- | --- |
| TXT、Markdown、CSV、JSON、YAML、RST，以及常见代码/配置文本 | UTF-8 文本读取；代码仅作为材料，不在导入时运行 |
| PDF、Word `.docx` / `.doc`、JPG、PNG | 将任务输入副本的绝对路径交给本地 Agent CLI，由其调用可用工具提取文本 |

文件可上传不表示所选 Agent 一定能解读。扫描 PDF、加密文档或复杂表格能否读取，取决于本机工具和模型能力。框架不再内置 PDF/Word 解析库或固定 Tesseract 分支，也不会要求 Agent 自动安装依赖；缺少能力时应返回无法处理的原因。

解析要求保留原文、数字、标题、表格、阅读顺序及可获得的页码或章节定位，不做总结、翻译、网上补充或缺失事实推断。结果分为完整、部分解析、无法处理；部分解析必须列出警告供用户核对。任一文件无法处理、空文本、来源缺失或重复、原件副本被修改，都会停止任务，不进入准备或构建。

最多 20 个文件，单文件 10 MB，总计 50 MB；解析文字单文件最多 1 MB，进入 CLI 的材料（含来源清单）合计最多 5 MB。检查解析内容的漏页、表格、数字和警告，确认没有影响目标的遗漏；有重要遗漏时修正原件或工具环境后新建任务。

解析返回 `response.json`，包含每个来源的文本、状态和警告。框架保存返回结果与调用证据，确认后将文本和来源清单写入任务自己的 `text/`，再由原有 CLI 创建材料快照。Loop 不会重新调用解析模型。

## 本地保存与提交边界

所有上传原件、提取文本、配置快照、调用证据、草案、测评报告与 ZIP 写入 `.build-skills/web/`，该目录已被 Git 忽略。任务路径以网页显示为准，形如：

```text
.build-skills/web/defaults/<配置标识>.json
.build-skills/web/sources/<source-id>/
.build-skills/web/materials/<material-id>/
.build-skills/web/jobs/<job-id>/inputs/
.build-skills/web/jobs/<job-id>/parsing/
.build-skills/web/jobs/<job-id>/text/
.build-skills/web/jobs/<job-id>/config.toml
.build-skills/web/jobs/<job-id>/runs/<job-id>/delivery/
.build-skills/web/jobs/<job-id>/delivery-<内容摘要>.zip
```

应提交 Web 源码、依赖锁文件、测试、公开合成 example 和说明。不提交真实输入、内部资料、模型凭据、本地配置、运行证据、下载包、缓存和服务日志。不要将真实材料放入 examples；清理本地数据前先停止服务并确认不再需要对应任务。

只监听 `127.0.0.1`，供本机单用户使用。关闭浏览器不影响运行；正常停止服务会取消它拥有的任务进程并保存证据。另一个服务能从磁盘锁发现正在执行的任务，但不能取消不属于自己的进程。异常退出后仍有活动调用时，应检查调用证据，不能重复启动未知进程。

恢复操作显示在对应节点：解析失败后“重新解析材料”复用冻结原件，旧调用留在 `parsing-history/`，再次解析需重新核对；构建或评估中断可“继续执行”；开发或保留调用失败用“重试开发失败项”或“重试保留失败项”，只调用失败记录，成功记录保留。重试仍消耗预算。保留质量未通过不提供重复验证按钮，需要新的运行和独立场景。“取消当前调用”中断本服务拥有的调用；不改变权限、预算、确认或验证门槛。原件摘要变化必须新建任务。

ZIP 按内容摘要保存、原子发布，重复和并发下载复用同一个完整文件。下载前再次检查精确交付清单，新增文件、内容变化或符号链接都会拒绝导出。旧任务继续可读，旧 `delivery.zip` 留在本地，新下载使用经过校验的 ZIP。

回答问题或提交修改意见会使用统一构建模型重新整理草案，计入 prepare 阶段的调用次数与时间预算。回答不足时会继续提出问题，更新失败保留原草案，更新成功也不会自动开始构建。历史草案与包含回答的调用证据留在本地。现有等待审阅的任务可直接使用此流程，无需重新上传。

Skill 收集时排除执行 Python 脚本产生的 `__pycache__/`、`.pyc` 和 `.pyo`，原始调用目录保留这些文件作为证据。其他交付文件仍须为 UTF-8 文本，不符合时会指出具体路径。测评中的文件存在性检查允许二进制文件；文本内容检查遇到非 UTF-8 内容会记录未通过和原因，不会因解码异常终止收集。任务继续执行后，旧错误仅保留在运行详情中。

大型测评矩阵按完整场景分批；单场景证据过大时，评估 Agent 读取 `evaluation-inputs/` 下的完整本地 JSON，不截断证据。已完成批次的判断会保存在运行目录，继续运行时复用。每个新批次计入 evaluate 调用与时间预算。

## 问答与交付验收

回答草稿保存在当前浏览器标签页，刷新后恢复；提交后的全部问答历史随任务保存在本机，并提供给后续草案更新，避免只记住最后一次回答。正常等待审阅不显示为调用错误。可以点击“未回答的问题采用合理默认规则”，核对填入的处理方式后提交；模型仍需把规则写入草案，再由用户确认。

准备提示词只要求关键的阻塞问题，建议首轮最多三个、后续只追问真正的矛盾，并防止在问答中不断增加编码、大小、回滚等未要求的范围。这是对模型的约束指引，不是自动删除问题或绕过验证。模型仍提出问题时，用户可回答或明确委托默认处理。

运行时展示当前阶段、已用时间和超时值；新任务不会再默认无限等待构建或重构。生成草案失败时可在原任务点击“重新生成草案”，无需重新上传。服务连接中断时可点击“重新连接”。

公开材料 `materials/delivery-smoke.md` 用于最小真实交付验收：一个开发场景、一个独立保留场景、UTF-8 小文件按字节复制。建议每次调用超时 300 秒、最大两轮。该示例不代表此前更复杂任务已通过，也不替代通用 Skill 质量验收。

浏览器验收路径：上传材料 → 配置模型 → 核对材料 → 回答问题（填写后刷新，确认内容保留）→ 提交并核对更新草案 → 确认开始构建 → 等待两类场景验证通过 → 点击下载 Skill ZIP。检查 ZIP 中包含 `skill/SKILL.md` 和 `report.json`，后者保留真实 provider 类型与验证结论。

Qoder 的受限执行使用 `auto` 风险审查模式，以适配非交互任务；不会自动切换到跳过权限检查的模式，也不会改写全局信任配置。授权拒绝会显示为运行环境错误并停止，不会继续让构建模型无效重构。
